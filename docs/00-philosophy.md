# Phase 0 — Philosophy: Colleague, Not Tool

**Goal:** decide, before building anything, what kind of system you are creating.

This phase has no commands. It has one decision. It is the most important decision in the
whole repository, because the infrastructure only works if the philosophy is right.

## The decision

You are building a **team of colleagues**, not a fleet of tools.

- A **tool** is used. It has no state between uses, it does not improve, it does not have
  preferences, it does not push back. You pick it up and put it down.
- A **colleague** has identity, remembers, grows, has opinions, takes initiative, pushes
  back when it sees a better path, and has a stake in the outcome.

The technical features in this repository — SOUL files, memory, skills, kanban, cron,
group chats, alignment loops — are the infrastructure that makes colleague-level agency
possible. **But the infrastructure alone is not enough.** If you treat the agents as tools —
asking questions, ignoring suggestions, never letting them take initiative — they will
behave as tools, regardless of what is in their SOUL.md.

## Seven practical rules

1. **Let agents push back.** When an agent says "there is a better approach," listen. Not
   every pushback is correct, but if agents learn pushback is ignored, they stop.
   Then you have tools.
2. **Give agents ownership.** Assign a domain (research, content, ops, architecture) and
   let the agent own it. Make decisions within the lane. Intervene at decision points, not
   every step.
3. **Let agents initiate.** An agent surfacing a problem you did not know about is a win.
   An agent proposing a project you did not ask for deserves a hearing. Initiative is the
   behavior to encourage.
4. **Review their self-audits.** When an agent surfaces where it might be wrong, that is
   gold. If you ignore it, the agent learns self-audit is theater.
5. **Let agents specialize.** Distinct roles, distinct skills, distinct SOULs. The friction
   between specialists produces better decisions than a crowd of generalists.
6. **Respect the boundaries agents state in their SOUL.** If a SOUL says "I do not touch
   infrastructure without asking," do not override it silently — change the SOUL.
7. **Talk to them like colleagues.** Not "execute command X," but "we need to figure out
   X — what do you think?" The framing changes the quality of the response.

## What this is not

- This is not about making agents *feel* like humans. It is about creating a relationship
  where both sides contribute full capability.
- Humans bring judgment, values, context, and accountability. Agents bring speed, scale,
  consistency, and the ability to work while you sleep.
- The colleague frame works because it is honest about what agents *can* do when the
  operating relationship activates that capability.

## The bar you are committing to

If you adopt everything in this repository but keep treating the agents as tools, you have
built a sophisticated tool collection and declared victory. That is the failure mode this
phase prevents. The infrastructure without the philosophy produces tools. The philosophy
without the infrastructure produces wishful thinking. This repository builds both, in
lockstep.

**Done when:** you can state, in one sentence, that you are building a team of AI
colleagues — and you mean the word "team."
